**還原：** 重新執行第 1 階段的函式檔 `20261126100300_bfv2_p1_functions.sql`（會把函式還原成現在的版本），再執行本檔最下方註解裡的刪除語法。預約函式因為回傳欄位不同，要先刪除再還原，檔案裡有寫。

**執行後線上的影響（重要）：** 從執行到新版程式部署完成之間——預約仍可成立（直接變成已確認，但舊畫面還寫「等教練確認」）；學員過了取消期限按取消會看到「操作失敗」。建議離峰時段，執行完立刻部署。

**上線前請另外跑一次這個查詢**（看有沒有「早該被自動取消、但因為舊排程只掃 48 小時而還在」的時段；執行這個檔後 5 分鐘內它們會被一次取消並通知學員）：

```sql
select s.id, s.start_at, sv.name, sv.min_attendance, sv.cancel_deadline_hours,
       (select count(*) from public.bookings b
         where b.slot_id = s.id and b.status in ('pending', 'confirmed')) as active
  from public.availability_slots s
  join public.services sv on sv.id = s.service_id
 where s.status <> 'cancelled'
   and sv.min_attendance >= 2
   and s.start_at > now()
   and s.start_at - sv.cancel_deadline_hours * interval '1 hour' <= now()
 order by s.start_at;
-- 其中 active < min_attendance 的時段，會在這個檔執行後 5 分鐘內被自動取消並通知學員。
-- active >= min_attendance 的會被這個檔最後一段補上成班時間，不會被取消。
```

### 這個檔最後一段是資料變更（請特別看）

自動取消從這個檔開始改看「有沒有成班時間」。上線當下那些**人數已經達標、只是還沒有成班時間**的團班時段，如果不同時補上，下一次排程（最長 5 分鐘內）就會被誤取消。所以「現存時段補上成班時間」放在這個檔的最後一段，跟函式同一次執行，不能拆開。這一段只補還沒有成班時間的時段，重跑不會重複。執行前的預覽查詢寫在檔案裡那一段的上方。

## 第 4 個檔　請假申請的函式

**檔案：** `docs/superpowers/plans/sql-drafts/20261127100200_bfv2_p2_leave_functions.sql`

不改任何表的結構，新增 5 支函式：

| 函式做的事 | 誰可以用 | 規則 |
|---|---|---|
| 學員送出請假申請 | 學員本人 | 預約已確認、尚未開課，而且「已過取消期限」或「團班已成班、自己取消會讓人數低於開班人數」；原因必填；可附一個想改去的時段；同時只能一筆審核中；被不同意過不能再送；撤回後可以再送 |
| 學員撤回 | 學員本人 | 只有審核中可以撤回 |
| 教練處理 | Owner、該時段的助教 | 同意改期（只能同意學員附的時段，當下重新檢查名額與到期日）／同意退回／不同意；開課後不能再處理 |
| 系統：開課時自動不同意 | 只有排程 | 開課時仍審核中 → 不同意，記為系統處理 |
| 系統：第二次提醒 | 只有排程 | 開課前 2 小時（平台設定）仍審核中、而且是更早之前送出的 → 再提醒教練一次，只提醒一次 |

**還原：** 檔案最上方有 5 行刪除語法。
**對線上的影響：** 無（新函式，舊版程式不會呼叫）。
**已依你的決定補上：** 教練選「不同意」時處理說明必填；同意改期、同意退回選填。
